# Build step 1 gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close build step 1 with one tidy-up PR: an evaluation baseline written by the runner, a Floorplan map of the real code, every deferred review point given an outcome, the Build 1 issues triaged, and a whole-repository review run last.

**Architecture:** Mostly docs and small fixes. The only new code is a `--report` option on the evaluation runner, which turns its results into a Markdown file so no figure is retyped. Everything else is checking, fixing and recording, in the order the design sets: report, ledger and triage, map, then the review.

**Tech Stack:** Python 3 (FastAPI backend, pytest, uv), Next.js website (Vitest, Playwright), Floorplan 0.11.0, `gh`.

**Spec:** `docs/superpowers/specs/2026-11-23-build-1-gate-design.md`. Issue: #106 (`[61]`).

## Global Constraints

- One branch, `chore/build-1-gate`, in the worktree `../layover-gate-1`; one PR that closes #106.
- No new features, widgets, endpoints, schema changes, dependencies or model calls; the template answer stays `llm: none`.
- "Small" fix: one or two files, with its test, no product choice, no new dependency. Anything bigger becomes a `noticed` issue.
- A fix that changes behaviour comes with a test that fails without it; assertions are never weakened.
- Traveller-facing text: only broken text is changed; each change is listed before → after for the owner, and the PR does not merge until the owner approves them (owner, 23 Nov 2026: "Fix now, you review in PR (Recommended)"). Approved wording that isn't broken is never changed.
- Ledger outcomes are exactly: fixed here, issue, already fixed, no longer applies, accepted earlier.
- Tokens are never written as `0` when no model call was made.
- Floorplan: confirm version 0.11.0 before running; never tick Health; `docs/floorplan/design.html` stays.
- No agent attribution in commits or the PR. Conventional Commit titles.
- `make check` passes before every push.

## Review Focus

1. **`--report` together with `--case`:** a one-case report could be committed as a gate baseline. Expect an argument error (exit 2) when both are given. Test in Task 1.
2. **A run with a FAIL:** the report must still be written and show the FAIL with its detail, and the command must still exit 1, so a broken baseline is visible, not hidden. Test in Task 1.
3. **The report's folder doesn't exist yet:** expect it to be created, not a crash. Test in Task 1.
4. **No git available** (for example in a container): the commit line reads "not known", never empty or a crash. Test in Task 1.
5. **A ledger point marked "already fixed" that isn't:** the outcome cites the file and line or commit that shows the fix, and the Task 2 reviewer spot-checks at least five of them against the code.

`totals_line_from(stdout)` is a two-line helper in the test file that returns the line starting with `total `. The FAIL test fills its body the same way as the others. It replaces `run_case`, runs `main(["--report", …])`, and asserts exit code 1 and `FAIL` in the file. This also covers the ledger's Task 12 note: "no test of main() exit codes".

- [ ] **Step 2: Run them and check they fail**

Run: `cd backend && uv run pytest tests/layover_evals/test_runner.py -v`
Expected: FAIL. The import error names `ReportInfo` and `render_report`.

- [ ] **Step 3: Implement**

`render_report` writes these, in order:
- the heading `# Evaluation report`;
- lines for the date, the commit and the command;
- `Quality: <totals_line>`;
- `Speed: <seconds rounded to 0.1> s for the whole run`;
- `Tokens:` either `none: this run made no model calls` when `model_calls == 0`, or a total;
- `Trip set:` either `none yet` or the count, followed by `<n> traveller script(s) on disk, not run yet` when scripts on disk outnumber the trips run;
- a table `| Case | Outcome | Detail |` with one row per result, using `Result.line()`.

`main` checks the arguments first (`parser.error` when `--report` and `--case` are both given). It times the run with `time.perf_counter()` and passes `model_calls=0` and `trips_run=0`, with a comment that no case runs a trip or a model until step 2. It counts `*.json` in `evals/travellers/` for `scripts_on_disk`. It writes the file with `parent.mkdir(parents=True, exist_ok=True)`, still prints as before, and still exits 1 on any FAIL.
